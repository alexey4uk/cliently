# Инструкция по настройке bePaid

Подключение платёжного шлюза bePaid для приёма оплаты подписок в приложении.

---

## 1. Регистрация и получение данных в bePaid

1. Зарегистрируйтесь в [bePaid](https://bepaid.by) (или в [песочнице](https://sandbox.bepaid.by) для тестов).
2. В личном кабинете получите:
   - **Shop ID** (идентификатор магазина)
   - **Secret key** (секретный ключ)
3. Для продакшена используйте боевые учётные данные из основного кабинета; для тестов — из песочницы (sandbox). У тестового и боевого магазинов разные Shop ID и Secret key.

---

## 2. Переменные окружения (.env)

Скопируйте блок настроек из `.env.example` и заполните значения.

### Обязательные

| Переменная | Описание | Пример |
|------------|----------|--------|
| `BEPAID_ENABLED` | Включить приём оплаты через bePaid | `true` или `false` |
| `BEPAID_TEST_MODE` | Режим песочницы (true) или боевой (false) | `true` для тестов |
| `BEPAID_SHOP_ID` | Shop ID из кабинета bePaid | `365` |
| `BEPAID_SECRET_KEY` | Секретный ключ из кабинета bePaid | строка из ЛК |
| `BEPAID_CURRENCY` | Валюта платежей | `BYN` (или `USD`, `EUR` по документации) |

### Опциональные

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `BEPAID_GATEWAY_BASE` | URL API шлюза | Зависит от `BEPAID_TEST_MODE` (sandbox / production) |
| `BEPAID_CHECKOUT_BASE` | URL чекаута | Аналогично |
| `BEPAID_DEFAULT_PAYMENT_METHOD` | Способ оплаты: `redirect` или `widget` | `redirect` |
| `BEPAID_CHECKOUT_LANGUAGE` | Язык интерфейса чекаута | `ru` |
| `BEPAID_WEBHOOK_URL` | Путь или URL для webhook (см. ниже) | `/webhooks/bepaid` |
| `BEPAID_VERIFY_WEBHOOK_SIGNATURE` | Резерв под проверку подписи (пока не используется) | `true` |
| `BEPAID_SUCCESS_URL` | Путь редиректа после успешной оплаты | `/subscription/payment/success` |
| `BEPAID_DECLINE_URL` | Путь при отклонении | `/subscription/payment/decline` |
| `BEPAID_FAIL_URL` | Путь при ошибке | `/subscription/payment/fail` |
| `BEPAID_CANCEL_URL` | Путь при отмене пользователем | `/subscription/payment/cancel` |
| `BEPAID_LOGGING` | Логировать запросы/ответы bePaid (для отладки) | `false` |

**Важно:** `APP_URL` в `.env` должен совпадать с тем адресом, по которому сайт доступен снаружи (нужно для callback-ссылок и webhook).

---

## 3. Webhook (уведомления о статусе платежа)

bePaid отправляет уведомления о смене статуса платежа на ваш сервер. Без настроенного webhook подписка не будет активироваться после оплаты.

### URL webhook

- В приложении обрабатывается маршрут: **`POST /webhooks/bepaid`**.
- Полный URL для bePaid: **`https://ваш-домен.ru/webhooks/bepaid`** (подставьте ваш `APP_URL` или домен).

В `.env` можно задать:

- **Относительный путь** (рекомендуется):  
  `BEPAID_WEBHOOK_URL=/webhooks/bepaid`  
  Итоговый URL будет: `APP_URL` + этот путь.
- **Полный URL** (если домен приложения отличается от того, куда стучится bePaid):  
  `BEPAID_WEBHOOK_URL=https://другой-домен.ru/webhooks/bepaid`

### Аутентификация webhook

bePaid отправляет запросы с HTTP Basic Auth: в заголовке `Authorization` передаются ваш **Shop ID** и **Secret key**. Приложение сверяет их с `BEPAID_SHOP_ID` и `BEPAID_SECRET_KEY`. Настраивать что-то вручную в bePaid для Basic Auth не нужно — они подставляют учётные данные магазина сами.

### Что проверить

- Сайт доступен по HTTPS (для продакшена).
- URL webhook доступен извне (нет блокировки файрволом, корректный виртуальный хост).
- После изменения `.env` перезапустите очередь (если используете queue):  
  `php artisan queue:restart`

## 4. Режимы работы

### Тестовый режим (`BEPAID_TEST_MODE=true`)

- Используются адреса песочницы bePaid (sandbox).
- Указывайте **Shop ID** и **Secret key** из [sandbox.bepaid.by](https://sandbox.bepaid.by).
- Подходит для проверки сценариев без реального списания денег.

### Боевой режим (`BEPAID_TEST_MODE=false`)

- Используются боевые адреса bePaid.
- Указывайте **Shop ID** и **Secret key** из основного кабинета bePaid.
- Обязательно проверьте оплату тестовым платежом перед запуском для пользователей.

---

## 5. Проверка настройки

1. Включите bePaid и задайте тестовые данные:
   ```env
   BEPAID_ENABLED=true
   BEPAID_TEST_MODE=true
   BEPAID_SHOP_ID=ваш_shop_id_из_sandbox
   BEPAID_SECRET_KEY=ваш_secret_из_sandbox
   ```
2. Убедитесь, что `APP_URL` в `.env` совпадает с адресом, по которому вы открываете сайт.
3. В приложении: оформите подписку и перейдите к оплате — должен открыться чекаут bePaid (в тестовом режиме — песочницы).
4. После успешной оплаты в песочнице проверьте:
   - редирект на страницу успеха;
   - активацию подписки в личном кабинете;
   - при необходимости включите `BEPAID_LOGGING=true`, выполните платёж и проверьте логи (не оставляйте включённым логирование надолго в продакшене).

## 6. Частые проблемы

| Проблема | Что проверить |
|----------|----------------|
| «Настройки bePaid не инициализированы» | Заполнены ли `BEPAID_SHOP_ID` и `BEPAID_SECRET_KEY`, нет ли лишних пробелов. После изменения `.env` перезапуск приложения/воркера. |
| Подписка не активируется после оплаты | Доступен ли webhook по `APP_URL`/домену извне, совпадают ли Shop ID и Secret key с теми, что в кабинете bePaid. Проверить логи при `BEPAID_LOGGING=true`. |
| 401 при запросе webhook | Совпадают ли учётные данные в bePaid и в `.env` (для текущего режима test/production). |
| Неверная сумма или валюта | В приложении инвойс создаётся с полем `currency`; по умолчанию используется `BEPAID_CURRENCY`. Убедитесь, что при создании инвойса передаётся нужная валюта и сумма. |
